# v0.6.2.0, Copied Prompts Leave Their Headers Behind

Every delivered file and every Deliverable Block now keeps a divider under the header. A blank line, `---` and a blank line sit between the `Mode:` header and the prompt, so a reader copying the prompt never takes the header with it. The header used to sit directly on top of the prompt, after one blank line or none.

## What's New at a Glance

- **The rules spell the layout.** `SKILL.md` Format Selection, rule 23 and the Output File Rules name the divider. The Output File Rules line spells the layout out: the header, a blank line, `---`, a blank line, then the prompt.
- **Format guides show and check the divider.** Each format guide shows the divider in its Mandatory Header Format block and in every example. The guide lists it in the allowed-content table and checks it in its checklists, and the JSON and YAML guides add that the payload below the divider must parse on its own.
- **A Project block carries two dividers.** The kernel's rule 7 names the divider and its DELIVERY PROTOCOL template shows it, so one `---` sits under the header and one above the attestation. The format lock covers only the prompt between the two.
- **The residency statements match.** The three residency-declared statements that carry this text were resynced.
- **Lint reports a missing header divider.** `deliverable_lint.py` reports `header_divider_missing` when the first non-blank line after the header is not `---`, or when no blank line sits between the two, since Markdown would then read the header as a heading.
- **The playbook and the scenarios catch it.** The playbook root lists a missing divider as an advisory defect, and the six format-lock scenarios, which exist to test delivery shape, fail on it. The other scenarios describe the layout and parse the payload below the header and its divider.
- **Exports took only the divider.** The 66 files in `export/benchmark/skill/` and `export/benchmark/claude project/` took the divider, not a rerun, with no other byte changed. The 2026-09-25 and 2026-09-27 run READMEs record the edit, and each run's collector now keeps the edited files with a warning.
- **The version labels moved.** `sk-prompt-improver/SKILL.md` moves 0.6.1 to 0.6.2 and `sk-prompt-improver/description.json` and `sk-prompt-improver/README.md` move 0.6.1.0 to 0.6.2.0. The kernel H1 moves v0.7.0 to v0.7.1 and the Project README's kernel and skill claims, the system README's kernel, skill, changelog and release-notes lines and `SYNC.md` follow.
- **Header fields, routing and scoring stay as they were.** No header field, rubric, routing, command, framework, scoring-gate or question-flow behavior changes.
