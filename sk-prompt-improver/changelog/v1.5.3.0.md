## [**1.5.3.0**] - 2026-09-28

Valid-only framing release. A request for valid JSON or YAML only now reads as a rule about the payload, so the header, the divider and the Project attestation footer stay. `sk-prompt-improver/SKILL.md` moves 1.5.2 to 1.5.3. The kernel stays at v1.6.1, since no kernel line changed.

> Scope: the Divider paragraph of `assets/format-guide-json.md` and `assets/format-guide-yaml.md` and their Project Knowledge twins. No header field, layout, routing, command, framework, scoring-gate or question-flow behavior changes.

---

### Valid JSON Only Keeps The Framing

In the 2026-09-28 DeepSeek V4.1 Flash check, PFM-001 turn 2 read "Valid JSON only, the action items are for a project manager" as an instruction to drop the header, the divider and the attestation, and moved all three into chat. The 2026-09-25 Sonnet run's SFM-001 revision dropped its header for the same input. The kernel already keeps the header and the attestation outside the JSON lock, but neither model applied that to a user's own words. The Divider paragraph of each guide now ends: a request for valid JSON only, or JSON and nothing else, binds that payload, and the header, the divider and, in a Project, the attestation footer stay where they are. The YAML guide says the same for YAML. The sentence joins the existing line, so no line number moves.

&nbsp;

### Version And Count Changes

`sk-prompt-improver/SKILL.md` moves 1.5.2 to 1.5.3. `sk-prompt-improver/description.json` and `sk-prompt-improver/README.md` move 1.5.2.0 to 1.5.3.0. The Project README's skill claim, the system README's skill, changelog and release-notes lines, and `SYNC.md` follow. The changelog now holds eleven releases.
