# v0.5.0.0, Defaults Fill Gaps, Revisions Are New Exports

A default now fills a gap in what the user asked for and never adds an output, field or section the user did not ask for, even when the reply flags it. A revision the user asks for after a delivery is saved as a new export under the next number, and a delivered export is never edited in place. A session with no Canvas panel renders the Deliverable Block as one fenced block at the very start of the reply, with no preamble about the missing panel or the mode detection, then the chat items as usual.

## Why This Release

In the Claude Sonnet 5 medium playbook run of 2026-09-25, a prompt asked for a meta description and a subheadings list the user never requested, and a revision added a `risks_and_blockers` extraction plus priority and dependencies fields. The fallback chain flags a default or an unvalidated assumption in the deliverable, and no rule said whether a flag could carry an output the user never asked for. On the operator's decision it cannot. In the same run, turn 2 edited `export/001` in place instead of saving `002`.

## What's New at a Glance

- **A default fills a gap and never adds what the user did not ask for.** The Objective in `SKILL.md` says a default fills a gap in what the user asked for, never adds an output, field or section the user did not ask for and is not made allowed by a flag. NEVER 4 and the Scope blocker line say the same, and a flag in the reply does not clear the blocker.
- **A revision after delivery is a new export.** Export-First Delivery in `SKILL.md` and the `AGENTS.md` export protocol say a revision the user asks for after a delivery is saved as a new export under the next number, and a delivered export is never edited in place. The Project writes no files and reports a `[###]` placeholder, so nothing on its side changed for this rule.
- **The Project kernel carries the same default rule.** The kernel Objective gains the same two default sentences, placed after the declared Objective statement so that statement stays verbatim. A Project run in the same report added a flagged field under the kernel's scope ban, which named no flag case.
- **A session with no Canvas panel leads with the deliverable.** The Delivery Protocol gains a no-Canvas rule: a session with no Canvas panel renders the Deliverable Block as one fenced block at the very start of the reply, with no preamble about the missing panel or the mode detection, then the chat items as usual. `PIR-002` failed on exactly that preamble.
- **The claude.ai Canvas rule stands unchanged.** The skill needs no counterpart, since its Claude Projects Delivery Override already puts one fenced Deliverable Block first.
- **Routing, commands, scoring and format locks stay as they were.** No routing, command, framework, scoring-gate or format-lock behavior changes, and no Project Knowledge file changes.
- **The version labels move forward.** `sk-prompt-improver/SKILL.md` moves 0.4.0 to 0.5.0, `claude project/Custom Instructions.md` moves 0.5.7 to 0.6.0 and `sk-prompt-improver/description.json` and `sk-prompt-improver/README.md` move 0.4.0.0 to 0.5.0.0. Both Project README claims follow, as do the system README's kernel, skill, changelog and release-notes lines and `SYNC.md`, while the changelog now holds seven releases.
