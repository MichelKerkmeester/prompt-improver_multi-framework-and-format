# v1.0.1.0, Deliver First, Route on the User's Words

A pasted prompt could steer the router, a request that carried everything still drew a question first, and a claude.ai reply put its copy unit somewhere that copied more than the prompt.

## Why This Release

A read-only comparison with Barter Deal Templates on 2026-10-18 found three gaps, and the operator approved fixing all three.

- **The pasted prompt routed the request.** `route_contract.py` read the whole message, so `Improve this prompt: "Write a blog post about photo editing for beginners"` routed to Image with VISUAL scoring, and a pasted prompt that summarises a video clip transcript routed to Video. The words that chose the mode belonged to the prompt being improved, not to the user.
- **Questions came before the deliverable.** The interactive flow asked a framework question at complexity 5 or 6, a simplification question at 7 or higher, a format question and a `$vibe` component library question, each before any prompt was written. Assumptions lived in four places: an `[Assumes: ...]` tag, a note inside the prompt, a field in the file header and the Project attestation footer.
- **The copy unit was wrong on claude.ai.** The kernel rendered the prompt as a Canvas Artifact with a `Mode:` header, a divider and an attestation footer inside it. A Canvas Artifact copies everything it holds, so a pasted JSON or YAML prompt carried the header and footer with it and no longer parsed.

## What's New at a Glance

- **Only the user's own words route.** The router sets the pasted prompt aside before it reads commands and keywords: fenced blocks, quoted spans of three words or more and, when neither is present, the text after a `this prompt:` style lead-in. A one-word quote such as `"midjourney"` stays and still routes. A message whose only content is a pasted prompt routes to Improve. The skill pseudocode, `benchmark/router/route_contract.py` and the kernel's Router Code carry the same `strip_source_prompt()`, and `kernel_parity.py` holds the skill and kernel copies equal.
- **Seven new router fixtures.** The photo probe and the video-clip probe now route to TEXT, a lead-in with no quotes routes to TEXT, a one-word quoted platform still routes to IMAGE, `$image` with a quoted prompt and an explicit image request stay IMAGE, and a fenced block alone routes to IMPROVE. `fixtures.json` holds 32 cases, all passing.
- **Deliver first.** A request that carries a prompt, or says what the AI should do, gets the improved prompt in the same turn. Only two things block delivery and get one comprehensive question first: no prompt and no description of the task, or two conflicting mode commands. A non-prompt request still gets its one reframe as prompt work.
- **The A/B/C framework question is gone.** At complexity 5 or 6 the runtime picks the best-fit framework and names the alternative as an open item when it would change the result. The operator approved dropping the question. At complexity 7 or higher the stated scope ships and the streamlined version is offered as an open item. With no format command the prompt ships as Markdown and JSON and YAML are named as an open item. `$vibe` writes no component library into the brief and lists the library choice as an open item.
- **Open items are the one home for assumptions.** Every default follows the deliverable as a numbered open item in the Deal Templates shape: the topic in bold, then a `- **Situation:**` bullet and a `- **Open:**` bullet with their text on the same line and no blank line inside or between items, because claude.ai joins a label on its own line to the line above it. The `[Assumes: ...]` tag, the note inside the prompt, the header field and the attestation footer are retired. `$raw` carries no open items.
- **The Project copy unit is the prompt alone.** A claude.ai reply opens with one bare code fence, no language tag, holding only the improved prompt. The `Mode:` header, the export-equivalent path, the score, the summary and the open items follow in chat. A bare fence wraps long lines on claude.ai while a tagged fence scrolls sideways, and its copy button copies exactly the prompt, so a pasted JSON or YAML payload parses. A Canvas Artifact copies everything it holds, which is why the prompt is never a Canvas Artifact. The CLI export keeps its header and `---` divider, because the file and the chat are separate there.
- **The Project reply linter follows the new contract.** `benchmark/grader/deliverable_lint.py` checks that the reply opens with an untagged fence holding only the prompt, that a JSON payload parses, that the `Mode:` header follows the fence in chat and that the open items are well formed.
- **The playbook follows the new contract.** Scenarios that graded a Turn 1 question as acceptable, a Canvas Artifact or an attestation footer now grade deliver-first and the bare fence, and the `$vibe` scenarios expect the library as an open item. Scenario files whose names end in `-canvas` keep their names so IDs and links stay stable.
- **The kernel moves to v1.0.1.** Its delivery rule, routing section, rules, delivery protocol, checklist and Router Code changed wording.

## Upgrade

A claude.ai Project needs the new `Custom Instructions.md` pasted and the changed knowledge files uploaded again: DEPTH Thinking Framework, Format Guide JSON, Format Guide Markdown, Format Guide YAML, Interactive Mode, Patterns and Evaluation and Visual Mode. The CLI needs no migration.
