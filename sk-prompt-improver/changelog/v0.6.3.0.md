# v0.6.3.0, Valid JSON Only Keeps the Framing

A request for valid JSON or YAML only now reads as a rule about the payload. The header, the divider and the Project attestation footer stay.

## Why This Release

A DeepSeek V4.1 Flash check on 2026-09-28 read "Valid JSON only, the action items are for a project manager" as an instruction to drop the header, the divider and the attestation, and moved all three into chat. A Sonnet run on 2026-09-25 dropped its header for the same input. The kernel already keeps the header and the attestation outside the JSON lock, but neither model applied that to a user's own words.

## What's New at a Glance

- **Valid JSON only binds the payload.** The Divider paragraph of `assets/format-guide-json.md` and its Project Knowledge twin now says that a request for valid JSON only, or JSON and nothing else, binds that payload, and the header, the divider and, in a Project, the attestation footer stay where they are.
- **The YAML guide says the same for YAML.** `assets/format-guide-yaml.md` and its Project Knowledge twin say the same for YAML.
- **The skill version moves from 0.6.2 to 0.6.3.** `sk-prompt-improver/SKILL.md` moves 0.6.2 to 0.6.3, and `sk-prompt-improver/description.json` and `sk-prompt-improver/README.md` move 0.6.2.0 to 0.6.3.0. The Project README's skill claim follows, as do the system README's skill, changelog and release-notes lines and `SYNC.md`.
- **The kernel stays at v0.7.1.** No kernel line changed.
- **No header field, layout or routing behavior changes.** Command, framework, scoring-gate and question-flow behavior does not change either.

## Upgrade

No migration required.
