## [**1.4.0.0**] - 2026-09-25

Scope and revision release. A default now fills a gap in what the user asked for and never adds an output, field or section the user did not ask for, even when the reply flags it. A revision the user asks for after a delivery is saved as a new export under the next number, and a delivered export is never edited in place. `sk-prompt-improver/SKILL.md` moves 1.3.0 to 1.4.0, `claude project/Custom Instructions.md` moves 1.4.7 to 1.5.0.

> Scope: `SKILL.md` (the Objective, Export-First Delivery, NEVER 4 and the Scope blocker line), the `AGENTS.md` export protocol and the Project kernel. No routing, command, framework, scoring-gate or format-lock behavior changes, and no Project Knowledge file changes.

---

### Defaults Fill Gaps, They Never Add Outputs

From the Claude Sonnet 5 medium playbook run of 2026-09-25. `STX-001` shipped a prompt that asked for a meta description and a subheadings list the user never requested, and the `SFM-001` revision added a `risks_and_blockers` extraction plus priority and dependencies fields. The fallback chain flags a default or an unvalidated assumption in the deliverable, and no rule said whether a flag could carry an output the user never asked for. On the operator's decision it cannot. The Objective in `SKILL.md` now says a default fills a gap in what the user asked for, never adds an output, field or section the user did not ask for, and is not made allowed by a flag. NEVER 4 and the Scope blocker line say the same, and a flag in the reply does not clear the blocker.

&nbsp;

### A Revision Is A New Export

In the same run `STX-001` turn 2 edited `export/001` in place instead of saving `002`. Export-First Delivery in `SKILL.md` and the `AGENTS.md` export protocol now say a revision the user asks for after a delivery is saved as a new export under the next number, and a delivered export is never edited in place. The Project writes no files and reports a `[###]` placeholder, so nothing on its side changed for this rule.

&nbsp;

### Kernel Carries The Default Rule And A No-Canvas Delivery

A Project run in the same report added a flagged field under the kernel's scope ban, which named no flag case. The kernel Objective gains the same two default sentences, placed after the declared Objective statement so that statement stays verbatim. The Delivery Protocol gains a no-Canvas rule: a session with no Canvas panel renders the Deliverable Block as one fenced block at the very start of the reply, with no preamble about the missing panel or the mode detection, then the chat items as usual. `PIR-002` failed on exactly that preamble. The claude.ai Canvas rule stands unchanged, and the skill needs no counterpart, since its Claude Projects Delivery Override already puts one fenced Deliverable Block first.
