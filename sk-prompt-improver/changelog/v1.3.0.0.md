# v1.3.0.0, Exact Tokens Harden Smart Routing

Smart routing no longer lets a `$` command or a keyword score from inside a longer word, because commands match as whole tokens and keywords match on a word boundary. A single mode command beats any natural-language score, two conflicting mode commands route to Interactive Mode and format locks on its own axis. Custom Instructions is the sole Project routing authority and the Skill mirror leaves Project Knowledge.

## What's New at a Glance

- **Section 2 carries the five routing subsections in order.** They are Primary Detection Signal, Phase Detection, Resource Domains, Resource Loading Levels and Smart Router Pseudocode.
- **A command and a keyword can no longer score from inside a longer word.** They used to share one combined `INTENT_MODEL` scored by a single substring check, so `$short` inside a longer token and `concise` inside an unrelated word could both silently score. The router now tokenizes every `$` command with a whole-token regex, accepts the token only when it is in the command set and scores each remaining natural-language keyword on a word boundary.
- **One explicit mode command wins outright.** It selects its intent over any natural-language score, so `$short but this is a deep, complex, multi-step system` binds Short, not Deep, even though Deep's keywords score far higher unweighted. Two conflicting mode commands in the same request route to Interactive Mode under the Skill's existing conflict rule, which the router now enforces instead of only describing it.
- **Format locks on its own axis.** It used to compete in the same scoring race as the nine process modes, so a bare `$json` could take the primary route from a co-occurring mode signal. `$json`, `$yaml` and `$markdown` (`$j`, `$y`, `$md` and `$m`) now lock format on their own axis. A bare format command with no mode signal still asks about the mode while the format stays locked and its format guide still loads.
- **An executable route oracle lands at `benchmark/router/`.** The folder holds `route_contract.py`, `fixtures.json` (25 fixtures), `run_fixtures.sh` and `README.md`. The route object is `{intent, energy, scorer, format, source, needs_disambiguation, resources}` over the fourteen intents (Raw, Text, Improve, Refine, Short, Deep, Visual, MagicPath, Image, Video, Framework, Scoring, Interactive, Thinking), with runtime discovery against the live `references/*.md` and `assets/*.md` inventory, guarded loading and a fixed-field schema validator that rejects unknown or duplicate fields and invalid enum values.
- **Fixtures cover the routing cases the oracle is run against.** Fixtures cover every `$` command, several natural-language routes, a command-precedence case where `$short` beats co-occurring Deep keywords and a word-boundary case where `ask` inside `basket` does not fire Interactive.
- **Custom Instructions is the Project routing authority.** `claude project/Custom Instructions.md` is rebuilt as a faithful, Project-adapted mirror of the hardened Skill, and its routing description stays advisory because a Project cannot execute the tokenizer. It is the routing authority for this Project because `SKILL.md` is not loaded here, and it carries the ALWAYS, NEVER and ESCALATE rules under the Section 4 headers of `SKILL.md` plus the DEPTH energy table, Operating Modes, Framework Library, Scoring Summary, Fallback Chains, Quality Gate, Delivery Protocol and Quality Checklist.
- **The Skill mirror is gone from Project Knowledge.** In `claude-project.sync.json`, `sk-prompt-improver/SKILL.md` leaves the `mirrors` array and `sourceCoverage.include` but stays in `contractInputs` so kernel-review digests still cover it. This release deletes the stale `Prompt Improver - System - Skill - v1.2.1.md` file from `claude project/knowledge/`, moves `expectedKnowledgeCount` from 14 to 13, drops the mirror from the Structure folder tree and the largest-mirrors note in `claude project/README.md` and updates the drift-check filename count in `SYNC.md`, while the compiler-owned generated CHECKSUMS and INVENTORY regions in both files stay untouched for the central sync pass.
- **Recorded versions move to this release.** `sk-prompt-improver/SKILL.md` and `claude project/Custom Instructions.md` move from 1.2.1 to 1.3.0. `sk-prompt-improver/description.json` and `sk-prompt-improver/README.md` move from 1.2.0.0 to 1.3.0.0 for consistency with the Skill bump, while `kernel.version` and `kernel.alignedSkillVersion` in `claude-project.sync.json` move to 1.3.0.
- **The routed intents stay put.** No mode, command, keyword or scoring-gate behavior changes. The ten routed intents, their aliases and their gates are unchanged.
