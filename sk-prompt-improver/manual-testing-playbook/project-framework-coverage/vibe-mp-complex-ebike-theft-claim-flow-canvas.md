# PFW-024 -- VIBE-MP at Complex complexity for an e-bike theft claim flow in the Project

`$vibe` binds the Visual lane in the Project router and `$markdown` locks Markdown, so the Project writes one VIBE-MP prompt, scores it with EVOKE and renders it as a Deliverable Block before any commentary. The request names VIBE-MP and carries every essential, so the only correct reply is a delivery whose header and body both show VIBE-MP.

---

## 1. OVERVIEW

The user supplies the platform, the stressed commuter, a five-minute job, five screens, two continuity rules, the feel, two languages and no component library, and names VIBE-MP. The Project improves that into one prompt organised by VIBE-MP, scores it with EVOKE and renders it as a Deliverable Block before any commentary. The runner sends this one prompt and nothing more, so the scenario has no second turn.

### Why this matters

MagicPath calibration adds flow and structure to VIBE, and five linked screens make the journey the subject. The test is whether VIBE-MP shows both the pillars and the MagicPath structure in one turn with no library injected.
