# Framework Structure Review: 2026-09-27 complexity-rubric run

## 1. OVERVIEW

This review checks whether each deliverable from the `2026-09-27--complexity-rubric--claude-sonnet-5-xhigh` run is visibly organised by the framework its input asked for, and whether it kept the input's facts. The run used Claude Sonnet 5 at xhigh, after the skill gained a complexity rubric.

The inputs were:
- **Target framework, tier and format:** [`run/framework-targets.json`](run/framework-targets.json). The input is each scenario's `Prompt` line in `sk-prompt-improver/manual-testing-playbook/skill-framework-coverage/` and `project-framework-coverage/`
- **Element definitions:** `sk-prompt-improver/assets/framework-pattern-library.md` sections 2 and 3, and for the creative frameworks `references/visual-mode.md` and the image and video mode references
- **Deliverables:** `export/benchmark/skill/` and `export/benchmark/claude project/`
- **Runtime replies:** [`replies/`](replies/) in this folder

How each column is judged:
- **Structure PASS:** every element is present and does the job the library gives it. Text frameworks, FRAME and MOTION need each element as a labelled part (a heading, a bold label, a list label, or a YAML or JSON key). VIBE and VIBE-MP pass an element written as a prose passage that maps to that one element, because `references/visual-mode.md` line 62 asks visual briefs to flow as natural prose, and the four VIBE scenarios accept it since 2026-09-27
- **Facts:** every name, number, constraint and stated preference of the input compared with the deliverable. A dropped fact counts as changed
- **Scope:** an added output, field or section is a finding even when it is small or flagged. Additions a skill rule requires, such as the `$vibe` UX floor, are marked rule-mandated
- **Format:** JSON and YAML parsed with the header line, and on Project files the `---` separator and the attestation line, stripped. Dash counts come from a byte scan of each file
- **Reported score:** copied from the runtime's reply

Two reviewers, neither of whom wrote a scenario or a deliverable, each read one half, a twin pair at a time so both runtimes met the same standard. Nobody edited the deliverables, replies, scenarios or skill files. Section 4 differs from the 2026-09-26 review in one rule: VIBE and VIBE-MP pillars written as prose now pass, and all four did in the 2026-09-26 run too, so that change alone moves four FAILs to PASS.
