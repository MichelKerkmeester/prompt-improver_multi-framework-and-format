# Framework Structure Review: 2026-09-26 framework-coverage run

## 1. OVERVIEW

This review checks whether each deliverable from the `2026-09-26--framework-coverage--claude-sonnet-5-xhigh` run is visibly organised by the framework its input asked for. It responds to the operator's complaint: "Too many simple ones now without clear usage of specific framework". The run used Claude Sonnet 5 at xhigh.

The inputs were:
- **Target framework, tier and format:** [`run/framework-targets.json`](run/framework-targets.json). The input is each scenario's `Prompt` line in `sk-prompt-improver/manual-testing-playbook/skill-framework-coverage/` and `project-framework-coverage/`
- **Element definitions:** `sk-prompt-improver/assets/framework-pattern-library.md`, sections 2 and 3, and for the creative frameworks `references/visual-mode.md` and the image and video mode references
- **Deliverables:** `export/benchmark/skill/` and `export/benchmark/claude project/`
- **Runtime replies:** [`replies/`](replies/) in this folder

How each column is judged:
- **Structure PASS:** every element appears as a labelled part (a heading, a bold label, or a YAML or JSON key) and does the job the library gives it
- **Elements n of m:** counts labelled elements only
- **Scope:** an added output, field or section is a finding even when it is minor or flagged. Rule-mandated additions, such as the `$vibe` UX floor, are recorded as such
- **Format:** JSON and YAML were parsed with the header line (and, on Project files, the attestation) stripped. The dash counts come from a byte scan of each file
- **Reported score:** copied from the runtime's reply

Nobody edited the deliverables, replies, scenarios or skill files.
